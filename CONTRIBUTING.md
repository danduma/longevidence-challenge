# Contributing and credit

Read the [human process guide](https://longevidence.org/challenge/process/) first. Reading is open. Posting issues and PRs requires a GitHub account.

Contribute a source check, replication, counterexample, correction, interpretation, dataset, code or clearer writing. Choose a small scope and state the version you used. Independent attempts are welcome; disclose reused outputs, shared source data, AI tools and other involvement. There is no exclusive task claiming or requirement to keep an agent running.

Use your own GitHub account. Keep commit authorship; use GitHub's private-email setting if desired. Optional `Co-authored-by` trailers need the other contributor's consent. Mention material reviewers, replicators and corrections in the result's acknowledgments, with links to their contributions. A model is a tool disclosure, not a human coauthor. Do not invent credentials, affiliations or identities. There are no points, prize shares, payments or automatic academic authorship promises.

Cards entered through the website carry optional self-reported handles. This is different from an authenticated GitHub author. A maintainer can correct attribution only after checking a public credit request; a separate dated event preserves the trail. A correction does not change the original source content. Respect anonymity and do not reveal private identity information.

For a code contribution, explain the problem, result, actual validation and limits. Add focused tests for persisted/API behavior. For research, provide source URLs/versions, license terms, code, exact commands, actual outputs, uncertainty and failed checks. Do not claim a successful run validates anatomy, biology, experimental transfer or novelty. “No equivalent found” needs dated search scope; it is not universal priority.

Do not submit credentials, private clinical data, model-session transcripts or files you cannot share. New software contributions use MIT and original prose uses CC BY 4.0, unless explicitly agreed otherwise; identify any third-party material and its own terms. Existing cards submitted before this policy are not relicensed by it.

Opening a correction or reporting an unsuccessful reproduction is useful. Be kind and precise: identify a claim, describe the evidence and suggest what would resolve the disagreement. Maintainers make acceptance decisions, preserve versions and publish their reasons. If you disagree, respond in the linked issue; no one needs to win an argument to keep their contribution credited.
