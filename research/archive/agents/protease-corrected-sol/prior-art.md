# Bounded prior-art check — 2026-11-26

The contribution claimed here is a numerical evaluation/provenance finding on one public release, not a new protease mechanism, correction algorithm, or new enzyme. Search non-retrieval is not evidence of novelty.

Sources actually inspected:

- Huber et al., *Data-driven protease engineering by DNA-recording and epistasis-aware machine learning*, Nature Communications 16, 5466 (2025), [DOI](https://doi.org/10.1038/s41467-025-60622-7). Full primary XML downloaded from Europe PMC; the main text, Methods, and source workbook were inspected. The paper already documents barcode outlier correction, discordant-duplicate rejection, binding-related recorder signal, noise blanking, FRET agreement, epistasis, and multi-site engineering. Those findings are prior art.
- [ProtRec pinned tree](https://github.com/JeschekLab/ProtRec/tree/8b9a1865108fa44c3e0a24ac20a59754222847ca), scripts 01_internal_controls, 01.1, 02–06 and their mapped/unmapped inputs/manual list. Source files are verified by Git blob SHA in sources/manifest.tsv. These explicitly contain the correction implemented here, including manually confirmed backbones. The [publication release](https://github.com/JeschekLab/ProtRec/releases/tag/1.0) has no attached additional files; its repository archive is archived as [Zenodo 15346003](https://doi.org/10.5281/zenodo.15346003), 86,476,068 bytes per metadata. Downloading that full duplicate archive was unnecessary because the needed barcode inputs were present. Archive metadata are retained.
- Source workbook MOESM4, sheets S8e, S7a, S7c and Fig2: exact final-population and numerical checks. MOESM5 ZIP inventory contains additional model figure arrays/CSVs, not a separate corrected barcode table. The published S7c parent branch differs from the current script's replacement branch; this is a version/provenance observation, not a biological result.
- [MLDEEP](https://github.com/BorgwardtLab/MLDEEP/tree/8cd6c319433be71644e79249a442b659d607c441): primary preprocessing source and previously pinned review source/configs. Its modeling task is combinatorial protease variants on 20 P1′ substrates, rather than the off-panel multi-mutant-substrate holdout here. It already reports complete protease-profile holdouts, read weighting, multi-output classifiers and epistasis-aware library sampling. No reproduced MLDEEP comparison or criticism is claimed here.
- [Structure-aware TEV specificity paper](https://pmc.ncbi.nlm.nih.gov/articles/PMC10523478/) (2023): independent review and current primary indexed text show protease/substrate prediction and combinatorial specificity engineering predate this analysis. We do not claim invention of substrate extrapolation testing.
- [Bioverse benchmark documentation](https://borgwardtlab.github.io/bioverse/implementations/benchmarks.html), [adapter documentation](https://borgwardtlab.github.io/bioverse/implementations/adapters.html): Huber compatibility benchmarking with Spearman and top-k enrichment already exists. We have not audited the current implementation's full data path, so make no claim it shares the upstream-population issue.
